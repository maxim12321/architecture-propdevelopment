## Описание внешней интеграции

Предполагается, что партнерская система предоставляет API, в котором можно:
* Открыть домофон по его ID
* Получить видео- и аудио-поток с домофона по его ID
* Добавить/изменить биометрические данные для домофона по ID
* Открыть шлагбаум по его ID
* Добавить номер автомобиля, для которого разрешен доступ к шлагбауму по ID

Для взаимодействия с API необходима аутентификация, которая будет выполняться
через API-ключ, который необходимо обновлять периодически (скажем, раз в месяц
или в полгода). Таким образом, у сервиса `smart-house-integration` будет
доступ ко всем добавленным домофонам одновременно, а ограничение на основе
данных пользователя будет выполняться на стороне PropDevelopment. Такой вариант
позволит не передавать бОльшую часть персональных данных пользователя в другую
систему.

Отдельного внимания заслуживают видео- и аудио-потоки с домофона. Они должны
передаваться строго в зашифрованном виде. Партнерское API использует публичный
ключ системы PropDevelopment для шифрования потока, а после передачи система
дешифрует его, используя соответствующий приватный ключ для передачи данных
клиенту.

Необходимо также организовать своевременную ротацию ключей шифрования, скажем,
обновлять их раз в месяц. Так как старые данные не хранятся в нашей системе,
ротацию можно делать достаточно просто, без необходимости перешифровывать
имеющиеся данные.

Аутентификация и авторизация собственников будет организована с помощью
существующих механизмов - через Keycloak (сервис `auth-service-1`). Нужно будет
внедрить (если еще не сделано) `ABAC`, тогда можно будет проще управлять доступом
конкретных пользователей к домофонам и шлагбаумом. Достаточно будет ввести
атрибуты для определения ID домофона или ID шлагбаума, на основании которых
можно будет управлять доступом пользователей.

Биометрические данные, а также номера автомобилей собственников **не хранятся**
в системе, а передаются напрямую в партнерские API в зашифрованном виде. Таким
образом упрощаются требования нашей системы к хранению данных и уменьшаются
риски компрометации. Ответственность за правильное хранение и шифрование этой
информации полностью переходит на систему-партнера.

Есть определенные риски в перехвате данных биометрии, но если правильно настроить
защищенные подключения (HTTPS) и шифрование передаваемых данных, таких проблем
быть не должно.
