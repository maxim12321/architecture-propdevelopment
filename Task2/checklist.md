# Проверочный лист безопасности

## Обоснования изменений

Пройдемся по потребностям бизнеса:
* Учитывая проблемы с жалобами клиентов касательно аутентификации, особенно важным становится пункт `I. Управление доступом`.
* Накапливаются данные для обработки -- тут нужна классификация, псевдонимизация, шифрование и прочие пункты из `II. Безопасность данных`.
* Реакция на инциденты и утечки у конкурентов -- тут важны пункты `III. Защита инфраструктуры` и `IV. Управление инцидентами`
* Соответствие требованиям законодательства -- в рамках аудита нужно классифицировать данные и проверить, как в компании с ними работают.
  Для этого снова подробно смотрим на `II. Безопасность данных`.

Также существуют проблемы при взаимодействии с партнерскими API. Для этого добавлен отдельный раздел в чеклист -- `V.2. Взаимодействие с партнерскими API`.

Отдельно про контроль данных -- про это есть некоторые вопросы в `I. Управление доступом`. Нужно настроить средства централизованного контроля доступа
на основе существующих реестров учетных записей. Все системы, обрабатывающие данные, должны пользоваться этим средством для проверки прав доступа.
